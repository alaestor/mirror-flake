# import-tree: Recursive Module Discovery

`import-tree` recursively discovers and imports every `.nix` file under a directory. Adding or removing a module is therefore just a file operation, avoiding merge conflicts in import lists while letting paths encode the project's structure.

Typically, import-tree is used to recursively import everything from `./modules/`, though project structures differ.

## How it works

`import-tree` expects all `*.nix` files in the scanned directory tree to be `flake-parts` modules. Any `.nix` file that is not a valid module will cause evaluation errors.

## Avoid legacy patterns

Do not place non-module `.nix` files in the scanned tree. For example, a `default.nix` containing `callPackage ./package.nix` will fail because `import-tree` expects every `.nix` file there to be a `flake-parts` module. Keep such files outside the scanned tree and reference them through `${inputs.self}/otherfolder/file.nix` when needed.

## Project structure

A typical dendritic flake using import-tree looks like:

```
flake.nix          # generated by flake-file
modules/
  default.nix      # top-level module config
  packages/
    hello.nix      # defines packages.hello
  apps/
    greet/
      default.nix  # defines apps.greet
  inputs.nix       # declares flake-file.inputs
```

Every `.nix` file under `modules/` is automatically imported — no manual import lists needed.
