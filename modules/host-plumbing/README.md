## global-config

Global configurations included automatically into all hosts

## host-identity

Provides a `hostIdentity` set that lets hosts configure a canonical name,
description, state version, and primary user of a NixOS host. The registry uses
`stateVersion` as the default for both `system.stateVersion` and
`home.stateVersion`, while `name` is wired through to `networking.hostName`
automatically.

This module is included in every host generated by the registry,
so callers only need to pass the identity values once at the
top level.

## registry

Declarative registry for NixOS hosts in this flake.
Each host is defined as an attribute in `config.host` and automatically
produces:
- A NixOS configuration under `flake.nixosConfigurations`
- Optional helper apps (ISO writer, nixos-anywhere deployer)

The generated NixOS configurations are pre-composed with
`global-config` and `host-identity` modules so that every host
inherits common base settings and a consistent identity.

Provides a per-host option schema to configure options related to
hostIdentity, along with nixpkgs, system, and modules.

Set host configuration capabilities such as enabling the `nix run`
`deploy` nixosAnywhere scripts, or `mkBootable` ISO scripts.

Plumbs the `hosts` into `nixosConfiguration` and associated `apps`
(depending on enabled capabilities).

## user environments

Hosts can attach Home Manager environments under `host.<name>.userEnvironment.<username>`.
Each attachment selects reusable Home Manager modules (including aspects and
preferences) and an activation mode:

- `integrated` rebuilds the environment with its NixOS host.
- `standalone` exposes `homeConfigurations."<username>@<host>"`.

NixOS features can contribute deferred Home Manager modules through
`userEnvironment.sharedModules`. These contributions are evaluated only for hosts
with a configured user environment, and are shared by both activation modes.
